# 双模型复核：先自己下结论，再派 reviewer

## 要修的问题

上一轮审 fxkit 时，主模型读完 skill 后的第一个动作是并行派了 4 个 explore 子代理去扫 outbox / server / cache / crudx。用户看到的是「一上来就 review」。

根因不是 reviewer 被调早了一步，而是第 1 步被外包了：

1. `.cursor/rules/dual-review.mdc` 始终生效，最显眼的一句是「给出最终结论之前必须调用 reviewer」。第 1 步只写「正常完成判断」，没有禁止派子代理。
2. `.cursor/skills/dual-review/SKILL.md` 第 1 步写「这一步你照常发挥，不受影响」，等于允许用 explore 代替自己读代码。
3. reviewer 的 description 是「给出方案后主动调用」，没有写「没有结论就拒绝」。主模型把「找 bug」理解成可以先派子代理。

只改 skill 不够。模型每轮都先看到 alwaysApply 规则；规则不改，下一轮还会先派子代理。

## 改动

三处对齐成同一条硬顺序：自己判断 → 结论落盘 → 再派 reviewer。写文件和派 reviewer 必须分成两次工具调用。同一次调用是并行的，文件还没写完，reviewer 按输入不完整拒绝。

禁止的范围只限这条流程里的第 1 步：子代理的输出如果会变成结论的内容，就是代替判断。「先扫几个包再汇总」不能改口叫无关搜索。和这次判断无关的搜索（例如只问某个符号在哪）可以派。

涉及现有代码的判断必须带文件路径和行号。reviewer 收到拒绝句时，主模型回到第 1 步重写结论，不能换个说法再派，也不能当成通过。

### `.cursor/rules/dual-review.mdc`

第 1 步改成：结论文件写出来之前，禁止派 `reviewer`、`explore`、`generalPurpose`。第 2 步要求文件里是判断本身，不是「请去审这个仓库」。第 3 步才调 reviewer，并写明不能和写文件并行。

例外、公开 API 收紧条件、对抗式复核脚本流程保持原样。

### `.cursor/skills/dual-review/SKILL.md`

删掉「照常发挥，不受影响」。第 1 步明确不许派任何子代理。第 3 步只允许派 reviewer，且必须等文件落盘。反模式补上三条：开工就派子代理、用 explore 代替自己的判断、写文件和派 reviewer 并行。

### `.cursor/agents/reviewer.md`

description 改成：没有结论全文或已落盘结论文件时直接拒绝，不要替主模型读代码。

输入检查增加拒绝句：`调用方还没有自己的结论，拒绝代做判断。` 覆盖「看看框架有没有 bug」「审一下整个仓库」以及文件里只有任务书、没有判断的情况。拒绝时不输出「可执行 / 需修正 / 方案不成立」。

输出格式、严重度、Go 必查项、禁止重写方案，都没改。

## 故意不做

- 不改 debate 脚本，也不加新的门禁脚本。文字门槛够用，再套一层检查是过度设计。
- 不改 reviewer 的 `model: claude-sonnet-5-5[]`。那是原有配置，和这次顺序问题无关。
- 不把 explore 从项目里禁用。和本次判断无关的搜索仍可派。这条边界写进了规则和 skill，不另做脚本。
- 文字门槛防的是「还没判断就派子代理」和「没有位置的空结论」。它证明不了模型真的读过那一行。不再加脚本去证明这一点。
